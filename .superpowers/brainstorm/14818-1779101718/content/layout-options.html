Review Requests List — Layout Options

How should the list show status, CI checks, and dates to help you prioritize what to review?

▼ NEEDS YOUR REVIEW (3)
✓CI alice/backend #42 Add rate limiting ⏳ REVIEW_REQ 2h ago
✗CI alice/frontend #17 Dark mode toggle ⏳ REVIEW_REQ 5h ago
◌CI bob/api #8 Refactor auth ⏳ REVIEW_REQ 1d ago [DRAFT]
▼ WAITING FOR AUTHOR (2)
✓CI alice/backend #39 Fix null pointer ✓ APPROVED reviewed 3d ago
✓CI bob/api #5 Update deps ↩ CHANGES_REQ reviewed 1d ago

A — Grouped Sections

Two groups: "Needs Your Review" (action items, highlighted) and "Waiting for Author" (already reviewed, dimmed). CI badge, review decision, and time shown inline. Reviewed items are visually deprioritized.

[Needs Review (3)] [ Waiting (2) ]
✗CI alice/frontend #17 Dark mode toggle 5h ago
by carol · REVIEW_REQUIRED · CI FAILING
✓CI alice/backend #42 Add rate limiting 2h ago
by carol · REVIEW_REQUIRED · CI PASSING
◌CI bob/api #8 Refactor auth [draft] 1d ago
by dave · REVIEW_REQUIRED · CI PENDING

B — Tabbed View

Two keyboard-navigable tabs: "Needs Review" and "Waiting". Two-line compact format per row: title+time, then CI/status/author on a secondary line. Tab-switchable, sorted by urgency (CI failing first).

REPO / TITLE CI REVIEW STATUS UPDATED
alice/backend #42 Add rate limiting ✓ PASS REVIEW_REQ 2h
alice/frontend #17 Dark mode toggle ✗ FAIL REVIEW_REQ 5h
bob/api #39 Fix null ptr ✓ PASS APPROVED 3d
bob/api #5 Update deps ✓ PASS CHANGES_REQ 1d

C — Single Sorted List

One unified list sorted by priority: unreviewed PRs at top, reviewed/waiting items dimmed at bottom. Columnar: repo/title | CI | review status | age. No toggling — scroll position signals priority.
